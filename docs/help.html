API Wrangler User Manual & Functional Reference

A high-performance, local-first Windows API testing workbench built on a content-addressed storage engine with full Git collaboration, zero cloud lock-in, and DPAPI-encrypted secrets.

⚡ Core Architecture Highlights

  • Git-First & Local-First: All collections, requests, environments, and mock rules exist as human-readable, canonical JSON files in your repository under api-wrangler/ or alongside wrangler.json.
  • Zero Cloud Telemetry: Runs completely offline on loopback and LAN without external cloud account requirements.
  • Hardware DPAPI Security: Secrets in {{secret:KEY}} are encrypted using Windows DPAPI and never leak into Git commits or execution logs.
  • Atomic Draft Recovery: In-flight typing is saved locally in memory and cache; sudden power interruptions or git switches never lose edits.

🚀 Quick Start (2 Minutes)

  1. Open a Project: Launch API Wrangler, navigate to the Project assets tab, and click Open project. If no path is entered, the folder browser opens. Choose any project folder containing a wrangler.json.
  2. Send a Request: Switch to the HTTP workbench tab, select your request from the Saved request dropdown or type a URL (e.g. http://127.0.0.1:5057/echo), and press Ctrl+Enter.
  3. Run a Collection: Pick a collection from the Collection dropdown and click Run collection to execute automated test iterations with full assertion reporting.

2. HTTP Workbench Tab

The primary testing interface for crafting requests, injecting variables and authentication headers, inspecting responses, and running collections.

Tab: HTTP workbench
Headers Body Query params Transport settings Variables Auth 
Accept: application/json
Authorization: Bearer {{secret:jwtToken}}
X-Correlation-ID: {{$guid}}

Request Features

  • Multi-part & File Uploads: Choose body mode file or form-data. Validates path existence before transmission to avoid sending empty bodies.
  • Cross-Origin Security: By default, redirects follow same-origin rules. Cross-origin redirects strip sensitive Authorization headers automatically.
  • TLS Error Override: Check Ignore TLS certificate errors for self-signed development certificates without modifying machine root certificates.
  • Response Formatting: Automatic JSON, XML, and HTML syntax highlighting with collapsible trees and byte formatting.

6. Mocks & Webhooks Tab

Built-in embedded loopback mock server and webhook listener for offline development, fault simulation, and webhook callback verification.

🔒 Security Guard: Loopback Only

The mock server binds exclusively to 127.0.0.1 to prevent exposing mock endpoints to the external network, unless explicitly configured.

Fault Injection Testing

  • Fixed Latency: Simulate slow networks (e.g. 2,000 ms delay).
  • TCP Abort / Connection Reset: Simulates abrupt socket disconnects.
  • Rate Limiting (HTTP 429): Validate client exponential backoff and retry policies.

8 & 9. Dataset Feasibility, Grid & Clipboard

High-performance tabular grid capable of rendering up to 100,000 cases using UI virtualization, with direct clipboard copy/paste to and from Excel or Google Sheets.

  • Ctrl+C / Ctrl+V: Full TSV/CSV format fidelity with Excel.
  • Fill Down: Quickly duplicate parameter sequences across rows.
  • Safe Export: Export validated data tables into CSV or project JSON without external disk leakage.

💻 Headless CLI Reference

The shared execution engine can run headlessly in CI/CD pipelines (GitHub Actions, GitLab CI, Azure Pipelines).

# Initialize a new project
api-wrangler init --project ./my-api --name "Production Regression"

# Validate project schemas and references
api-wrangler validate --project ./my-api

# Execute an entire collection with JUnit and HTML test reports
api-wrangler run --project ./my-api --collection "Auth & Payments" --environment "Staging" --reporter junit,html --output ./reports

# Execute a single ad-hoc request
api-wrangler send --url https://api.example.com/health --method GET

Diagnostics & Troubleshooting

Common Issues & Resolutions

  • "No wrangler.json was found in the selected project": Ensure you selected the folder containing wrangler.json or click Browse... to choose the folder directly.
  • "Port already in use": If the mock server fails to start, verify that port 5058 is not occupied by another instance or service.
  • "Upload file not found": If a request has body mode set to file, ensure the absolute path exists on disk before clicking Send.
